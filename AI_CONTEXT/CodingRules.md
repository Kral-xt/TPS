# 编码规则

## 分层约束

- Presentation 负责 UI、VFX、动画、相机和输入表现，不承载业务规则。
- Application 负责流程控制、系统调度和状态流转。
- Domain 负责游戏规则和数值计算，尽量不依赖 Unity API，不编写 MonoBehaviour。
- Infrastructure 负责配置、资源加载、对象池、持久化和 Unity 适配。
- 禁止跨层直接调用；跨层协作通过稳定接口或应用层服务完成。

## 修改约束

- 优先最小修改，保留现有公共接口和序列化字段名。
- 不修改无关模块、第三方插件或 QFramework 自动生成文件。
- 不删除资源、不批量移动文件、不修改 TagManager/Layer，除非获得用户确认。
- Inspector 字段使用清晰分组和中文说明；新增参数应可配置并设置合理约束。
- Unity 脚本修改后等待编译完成并检查 Console 错误。

## 审核重点

- P0：编译错误、空引用、生命周期错误、数据丢失、Prefab/序列化破坏。
- P1：更新顺序、多脚本冲突、重复绑定、对象池状态未重置、资源泄露和 GC。
- P2：可维护性、扩展性和低耦合改进。
